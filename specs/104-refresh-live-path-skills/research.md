# Phase 0 Research: Refresh live-path skill currency

No `[NEEDS CLARIFICATION]` markers survived the spec; this phase records the design resolutions
and the source-grounding sweep that backs every skill claim.

## R1 — Refresh `fs-skia-reconciliation` in place vs. new sibling skill

- **Decision**: Refresh the existing `.agents/skills/fs-skia-reconciliation/SKILL.md`; add a
  "Live retained render path (096–103)" subsection and rewrite the stale forward-looking lines.
- **Rationale**: The diff (067) and its wired live path (091→103) are one continuous story the
  skill already frames; splitting it fragments the reader's mental model and adds corpus churn,
  against FR-008's minimalism. The skill's existing **Disposition** section is the single source
  of truth for the module's status — updating it in place keeps that property.
- **Alternatives**: A new `fs-skia-retained-render` sibling (rejected — fragmentation, two
  Disposition sections to keep in sync); leaving it and only adding the host skill (rejected —
  US1 P1 explicitly requires the reconciliation skill be current, and it carries the most
  forward-looking-as-future language).

## R2 — US3 skill location: `.agents` domain skill vs. package skill

- **Decision**: New `.agents/skills/fs-skia-controls-host/SKILL.md` (a repo-local domain skill).
- **Rationale**: (a) Only `.agents/skills/**` is mirrored into `.claude/skills/**` and listed in
  `skillist-reference.md`; a `src/Controls.Elmish/skill/` package skill is **not** mirrored, so it
  could not meet FR-007's discoverability. (b) The host story is cross-cutting —
  `Controls.Elmish.runInteractiveApp` plus the `Controls.RetainedRender` per-frame wiring — which
  fits a domain skill better than a single-package capability skill. (c) Directly parallels the
  two existing `.agents` skills in this domain (`fs-skia-reconciliation`, `fs-skia-viewer-host`).
- **Id choice**: `fs-skia-controls-host`. Verified free in both the `.agents` id namespace and the
  package-skill (`src/*/skill`) namespace (one shared `SkillSyncCheck` namespace — the
  `fs-skia-viewer-host`/085 collision precedent). Chosen over `fs-skia-interactive-host` to name
  the package it documents (`Controls.Elmish`) and to read as distinct from the consumer-facing
  `fs-skia-viewer-host`.
- **Alternatives**: package skill `src/Controls.Elmish/skill/` (rejected — not mirrored/listed;
  also pulls in the controls-elmish package-surface routing for no benefit); fold the host
  material into `fs-skia-viewer-host` (rejected — spec A2 keeps the maintainer host seam distinct
  from the consumer hosting guide).

## R3 — Does the change need a constitution amendment?

- **Decision**: No.
- **Rationale**: The constitution's "Current FS.Skia.UI capability skills" registry (lines
  261–286) is **selective** — it lists package skills and two `.agents` skills
  (`fs-skia-layout-readability`, `fs-skia-evidence-mode`) but omits `fs-skia-reconciliation`,
  `fs-skia-viewer-host`, `fs-skia-typed-controls`, etc. A new domain skill in the same class as
  those omitted ones does not require a registry entry, so no amendment is needed. This preserves
  the Tier-2 / zero-governance-churn posture.

## R4 — Mirror & skillist regeneration mechanism

- **Decision**: Hand-edit only the canonical `.agents/skills/**` files (+ the `src/Controls/skill`
  package skill); regenerate `.claude/skills/**` and `skillist-reference.md` with
  `./fake.sh build -t RefreshSurfaceBaselines`.
- **Rationale**: `.claude/skills/**` is byte-identical-generated by `SkillTreeGen`; a hand-edit
  trips `SkillSyncCheck`. A new `.agents/skills/<id>` requires `RefreshSurfaceBaselines` to
  regenerate `skillist-reference.md` (and per the `refresh-surface-baselines-skillist-reference`
  lesson, per-package surfaces too). Verify the regeneration via `Governance.Tests` (trailing-
  newline drift is the known gotcha).
- **Alternatives**: hand-mirroring (rejected — guaranteed drift and gate failure).

## R5 — Routing expectation for the diff

- **Decision**: Run `./fake.sh build -t Route` and obey its printed gate list; do not assume.
- **Rationale**: US1/US3 edit `.agents/skills/**` (governance paths → skill gates). US2 edits
  `src/Controls/skill/SKILL.md`, which lives under `src/Controls/**`; the feature-102 precedent is
  that even comment-only/markdown edits under `src/Controls/**` escalate to the
  controls-public-surface set (≈14 gates) plus `EvidenceGraph`/`EvidenceAudit`, despite zero
  `.fsi` delta. So the realistic expectation is the escalated set, but `Route` is authoritative.
- **Known gotchas to carry into implementation** (from prior live-path features):
  - The window-visibility audit fires on literal image-evidence filenames in `tasks.md`/feature
    text → an honest full not-applicable evidence set may be required.
  - `EvidenceAudit` blocks until `readiness/evidence-audit.md` carries a verdict token and
    `generated-validation.md` reports `package-resolution=resolved` / `package-mismatch=false`.
  - Some gates rewrite their own readiness files (aggregate-hang-diagnostics reverts to a stale
    020 template) → re-author after running gates.
