# Phase 0 Research: Single-Source the Duplicated Governance Corpus

This feature is structural, not editorial. The research below resolves *how* to
collapse the four duplication classes named in the spec onto canonical sources
with generated, currency-checked copies — reusing the repository's existing
single-source-and-generate machinery rather than inventing a new framework.

## The existing pattern this feature extends

The repo already proves three working single-source pairs. Each is
**canonical source → pure generator → derived copy → currency gate → drift
diagnostic naming file + source**:

| Pair | Canonical | Generator | Derived copy | Currency gate |
| --- | --- | --- | --- | --- |
| Skill tree | `.agents/skills/**` | `SkillTreeGen.plan` | `.claude/skills/**` (+ `GENERATED.md`) | `SkillSyncCheck` |
| Routing contract | `build/Governance/Routing.fs` | `ContractView.render` | `validation.contract.yml` | `TargetMetadataDrift` |
| Constitution fragments | `.specify/memory/constitution.md` | `ConstitutionFragments.extract`/`splice` | spliced regions of `plan-template.md` / `tasks-template.md` | `TargetMetadataDrift` (folded) |

All three regenerate from one effect target, `RefreshSurfaceBaselines`
(`build/Governance/Engine/Update.fs:81`), and keep I/O at the single `Interpret.fs`
edge. The splice mechanism uses regex marker pairs
(`<!-- BEGIN GENERATED: constitution/<id> -->` … `<!-- END GENERATED: ... -->`),
replaces only the inner region, leaves bytes outside the markers untouched, and
leaves unknown markers in place (honest drift). This is the exact mechanism the
new generated copies will reuse.

## Decision 1 — Per-file token & obligation carriage (classes 1 + 2): marker-splice generation, hybrid by consumer

**Decision.** Introduce one canonical store of governed *prose blocks* (the
sentences that carry a `ContractToken` and/or satisfy a `GuidanceObligation`'s
concepts), keyed by id, each declaring the home files it must appear in. Render
each block into its home files via `BEGIN/END GENERATED: gov/<id>` splice markers,
regenerated by `RefreshSurfaceBaselines` and currency-checked. Follow the spec's
clarified **hybrid-by-consumer** rule:

- Where the home file is a shipped, template-owned, or `.agents`/`.claude` file an
  agent reads directly (constitution twins, SKILL.md, command twins, templates),
  the block stays present but is **generated + currency-checked**, not
  hand-carried. The `evaluateGuidanceCheck` scanner still asserts presence, and a
  new currency gate additionally asserts the spliced region equals canonical.
- Where the duplication exists **only** to feed an in-repo substring scanner (the
  echo lines — class 3, Decision 3), the copy is deleted and the scanner reads the
  canonical natural-prose block directly.

**Rationale.** The tokens (`[SEH]`, `synthetic-error-handling-approved`, the
controls tokens) are genuine prose an agent must read in each file, so they cannot
simply be deleted — they must be *generated identically* from one source. This is
the `ConstitutionFragments` pattern generalized from "first sentence of a
principle" to "arbitrary keyed block spliced into N files." `Guidance.fs` remains
the single home of the rule *set* (FR-004); the new store changes only how the
prose that satisfies those rules is *carried* into files.

**Alternatives considered.** (a) Have the scanner synthesize the tokens at scan
time and drop them from files entirely — rejected: agents reading the file would
no longer see the rule. (b) A brand-new generation framework — rejected by FR-007
/ Assumption: extend the existing splice, do not introduce a parallel one.

## Decision 2 — Constitution triple-maintenance (class 4): placeholder-bearing canonical fragment, two render modes

**Decision.** Promote a **placeholder-bearing principle-body source** to canonical
(extending `ConstitutionFragments` from first-sentence extraction to full-body
ownership). Two render modes are generated and currency-checked:

- `.specify/memory/constitution.md` — placeholders **substituted** with the
  repo's concrete values (e.g. the enumerated `Current FS.Skia.UI capability
  skills` list; concrete skip-mechanism and placeholder-exception phrasing).
- the two `constitution-template.md` twins
  (`.specify/templates/…` and `.specify/presets/fsharp-opinionated/templates/…`) —
  placeholders **preserved** (the directive/`{{…}}` form), and byte-identical to
  each other.

A substitution map (placeholder id → repo value) lives beside the canonical
source. Currency compares each rendered target against a fresh render.

**Rationale.** This is exactly the clarified end-state (spec Clarifications Q2 /
FR-007). The twins differ from `constitution.md` only at known placeholder points
(skill enumeration, skip mechanism, placeholder-exception examples); everything
else is identical 320-odd lines hand-maintained three times today. One canonical
body + a small substitution map collapses that to one edited source.

**Alternatives considered.** Make `constitution.md` canonical and generate the
templates by *blanking* concrete values — rejected: the clarification fixes the
**placeholder-bearing** form as canonical so the generic template is the source of
truth and the concrete repo file is a derived view.

## Decision 3 — In-file scanner echoes (class 3): delete the echo, scan the canonical prose

**Decision.** Remove the literal `Exact … phrases for scans:` echo lines and have
the scanner read the natural-prose list already present in the same file. The
catalogued echoes are:

- `Exact skill phrases for scans:` — `.specify/templates/tasks-template.md:218`,
  `…/presets/…/tasks-template.md:208`, `.agents/skills/speckit-tasks/SKILL.md:146`,
  `.claude/skills/speckit-tasks/SKILL.md:146`,
  `…/presets/…/commands/speckit.tasks.md:129`.
- `Exact readiness phrases for scans:` — the two `tasks-template.md` files and
  `speckit.tasks.md`.
- `Exact visual proof rejection phrases for scans:` and `Exact owner phrases for
  scans:` — `.agents/` + `.claude/` `fs-skia-layout-evidence/SKILL.md:118/125` and
  `template/base/docs/product.md:87/94`.

Where a home file genuinely needs the phrases for agent reading (the SKILL/command
twins, the template-owned docs) and they cannot be derived from in-file prose, the
phrases become a **generated** block under Decision 1's marker splice rather than a
hand-carried echo. The `.agents`→`.claude` copies remain `SkillSyncCheck`-governed.

**Rationale.** FR-006 is explicit: scanner-only duplication is single-sourced *by
consumer location* — delete where the scanner runs in-repo, generate-and-check
where the consumer is a shipped/agent file. `evaluateGuidanceCheck` already reads
whole-file content, so the natural list satisfies the token once the echo is gone,
provided the scanner's required phrases are matched by (or generated into) the
canonical block.

**Alternatives considered.** Keep echoes but mark them generated — rejected for the
in-repo-scanner case: FR-006 wants the echo *removed* there, not merely regenerated.

## Decision 4 — Currency gate placement & the new drift class

**Decision.** Add the new generated copies' currency check to the existing
`TargetMetadataDrift` composite (which already folds `validation.contract.yml`,
target-metadata, and constitution-fragment currency) rather than minting a new
top-level FAKE target, unless a generated artifact needs an independent gate. The
**new failure class** — a hand-edited *generated copy* that diverges from its
source — is surfaced by this currency check with a diagnostic naming the drifted
file **and** its canonical source, mirroring `ConstitutionFragments.currencyDrift`
and `SkillTreeGen.currencyDrift` ("… is stale — regenerate via `./fake.sh build -t
RefreshSurfaceBaselines`").

**Rationale.** FR-003 / SC-005 demand *no generated artifact without a guarding
currency gate*. Folding into `TargetMetadataDrift` reuses the proven
read→render→compare→diagnose shape and keeps the gate count stable (spec
Build-target impact: "No new top-level FAKE target is required unless a generated
artifact needs its own gate"). Each new generated artifact is enumerated against
its gate in the readiness audit (SC-005).

**Alternatives considered.** One new `GovernanceFragmentDrift` target — kept as a
fallback only if the composite grows unwieldy or an artifact needs isolated
failure ownership; default is to fold.

## Decision 5 — Reduction is measured, not targeted

**Decision.** Report the achieved corpus line delta (with reproduction commands)
and the maintenance-surface delta (files-touched-per-rule-change, before vs after)
in `readiness/structural-reduction.md`, using the existing
`ProseSizeAccounting`/`prose-size-accounting.md` instrument as the line-count
oracle. No fixed target line count; no reuse of any discredited historical figure
(FR-009, SC-002). The honest baseline is 056's **6772** lines.

**Rationale.** SC-002/SC-003/SC-006 require the reduction be *attributable to
collapsed duplication, not dropped rules*; pairing the line delta with the
duplication catalogue and a green `GeneratedGuidanceCheck` makes that auditable.

## Decision 6 — Routing, escalation, and Routing.fs currency

**Decision.** This change touches governance paths (`build/Governance/**`,
`.specify/**`, template-owned files), so `Route` escalates to the
`maintainer-verify` path automatically. `Routing.fs` is **not** expected to change
(no new path classes or gates), so `validation.contract.yml` must stay
byte-identical; if any routing edit becomes necessary it is regenerated and
`TargetMetadataDrift`-checked (FR-008). The serialized six-target order from
`CLAUDE.md`/`AGENTS.md` is the verification path.

**Rationale.** Matches the spec's Tier-2-internal-governance-that-escalates framing
and Assumption set; keeps the routing contract honest.

## Open questions resolved
