## Status Legend

- `[ ]` — pending
- `[X]` — done with real evidence
- `[S]` — done with synthetic evidence only (must be disclosed per Principle V)
- `[F]` — failed
- `[-]` — skipped (with written rationale)

`[S*]` is computed by the evidence audit, never written by hand. No `[SEH]`
task is expected for this feature — generation is real (the gate compares
regenerated bytes to on-disk bytes; parity is asserted against real
pre-migration rows; the correspondence test reads the real
`FS.Skia.UI.Controls.Typed` surface), so the Synthetic-Evidence Inventory stays
empty (SC-006).

## Vertical-slice rule (US phases)

A `[US*]` task may be `[X]` only when the maintainer-facing entry point was
actually exercised. Here the entry points are the FAKE targets:
`./fake.sh build -t RefreshSurfaceBaselines` (regenerate both files from the
single source) and `./fake.sh build -t ControlsCatalogGenerationCheck` (drift
gate). A green unit test alone does not satisfy `[X]` for a `[US*]` task — the
target invocation must be run and its transcript/report captured under
`readiness/`.

## MVU / effect boundary (build front)

The shipped `FS.Skia.UI.Controls` package gains **no** stateful workflow or
runtime effect (Principle IV N/A for the product). The generation *machinery*
nonetheless honours the build front's effect boundary: `CatalogGen.render` /
`spliceYaml` / `spliceFSharp` / `currency` are **pure** over in-memory text, and
all filesystem read/write happens only at the `Engine/Interpret.fs` interpreter
edge via the new `RegenerateCatalog` effect (peer of `RegenerateGovernedBlocks`).

## Governance risk levels

- **Small**: a fact edit in `catalogFacts` + `RefreshSurfaceBaselines` →
  focused validation is `ControlsCatalogGenerationCheck` + `Dev`.
- **Medium**: generator/render/splice/currency logic change → add
  `ControlsCatalogCheck`, `CatalogTests`, `TargetMetadataDrift`.
- **Broad**: routing/target-metadata change (`Routing.fs`, `Targets.fs`,
  `validation.contract.yml`) → the full escalated serialized FAKE order is
  required (T022). Aggregate FAKE results are **non-authoritative**; the
  authoritative per-gate verdicts are recorded in `readiness/` and named in
  `readiness/governance-risk-levels.md`. FAKE-backed targets run **sequentially**
  (shared `.fake` state) in the deterministic CLAUDE.md/AGENTS.md order.
