# Typed catalog generation — single-source design & drift gate

- **Authoritative command**: `./fake.sh build -t ControlsCatalogGenerationCheck`
  (currency/drift gate); `./fake.sh build -t RefreshSurfaceBaselines` (regenerate).
- **Artifact path**: `specs/066-typed-catalog-generation/readiness/control-catalog-generation.md`
  (PASS/FAIL report written by the gate).
- **Failure class**: `stale-generated-catalog` — a hand-edited generated region that
  diverges from `CatalogGen.catalogFacts`.
- **Next action on failure**: run `./fake.sh build -t RefreshSurfaceBaselines`, which
  re-splices both files from the single source.

## Feature tier & impact (T002)

- **Tier**: Tier-2 internal change for the shipped `FS.Skia.UI.Controls` package (no public
  API/behavior/dependency delta — the six `ControlDefinition` rows and `catalog.yml` content
  are byte-identical), carried with **Tier-1 artifact rigor** because `src/Controls/**`
  escalates via the `controls-public-surface` routing rule.
- **Affected layer**: `FS.Skia.UI.Build` only. No runtime dependency is added to
  `FS.Skia.UI.Controls` (FR-009) — the generator, gate, and effect all live in the build
  front.
- **Public-API impact**: none. `Catalog.supportedControls` / `ControlDefinition` are
  unchanged in shape and values; `Catalog.supportedCount () = 47`; all ten categories
  present. Surface baselines did not move (confirmed by an unchanged `PackageSurfaceCheck`
  expectation; no `.fsi` delta for the shipped package).
- **MVU applicability**: pure transform. `CatalogGen.render*` / `splice*` / `currency` are
  pure over in-memory text; the file reads/writes happen only at the `Engine/Interpret.fs`
  interpreter edge via the new `RegenerateCatalog` effect (peer of
  `RegenerateGovernedBlocks`). The drift gate reads both files at the same edge (the
  `TargetMetadataDrift` precedent).
- **Evidence obligations** (FR-010, SC-006): this file + `typed-catalog-parity.md`, both
  populated and disclosing that generation is **real**.

## Single source (FR-001)

`build/Governance/CatalogGen.fs` declares `catalogFacts : TypedCatalogFact list` — exactly
the six `065` controls `{ text-block, button, text-box, check-box, data-grid, stack }`, in
catalog file order. Each fact is the **one** place its `Id`, `DisplayName`, `Category`,
`Module`, `Purpose`, `RequiredAttributes`, `Events`, and `AccessibilityRole` are declared.
The remaining descriptive facts (common attributes, visual states, accessibility sub-fields,
examples, tests, base evidence, support status, owner) are reproduced from the same shared
constants the hand-authored rows use, so the rendered rows are byte-identical (FR-004). This
mirrors the `ContractView` (Routing.fs → validation.contract.yml) precedent: the canonical
value and its renderer live together in the build front.

The association to the `FS.Skia.UI.Controls.Typed` modules is enforced by the correspondence
test in `tests/Controls.Tests/CatalogTests.fs`: the fact set is exactly the six typed
modules, and each fact's `RequiredAttributes` map to real `Props` record fields
(`data-grid` keeps `Category = data` / `Module = DataGrid`).

## Per-control marked-region splice model (FR-002, FR-003, R2)

The six rows are **non-contiguous** in both files, so each row carries its own marked region
keyed by control id, with a file-appropriate comment token:

- `src/Controls/catalog.yml` — `# BEGIN GENERATED: typed-catalog/<id>` … row … `# END GENERATED: typed-catalog/<id>`
- `src/Controls/Catalog.fs` — `// BEGIN GENERATED: typed-catalog/<id>` … `definition …` row … `// END GENERATED: typed-catalog/<id>`

The 41 hand-authored rows lie **outside every marker** and are never read or written by
generation (verified: `RefreshSurfaceBaselines` produced no diff to the 41 rows,
`supportedCount: 47`, the ten categories, the `defaults:` block, or the public
`ControlDefinition` shape). `RegenerateCatalog` writes **both** files in one operation, so
the two outputs cannot diverge (partial-regeneration edge case cannot occur).

## Drift gate (FR-005, FR-006)

`ControlsCatalogGenerationCheck` is a standalone named gate (the `SkillSyncCheck` precedent,
not a `TargetMetadataDrift` fold — research R3) registered in the `controls-public-surface`
routing rule, so `./fake.sh build -t Route` lists it for any `src/Controls/**` change and
`Route --enforce` blocks on a stale catalog. The gate reads both files, computes
`CatalogGen.currency`, writes the PASS/FAIL report, and on drift `FailWith`s a diagnostic
that **names the divergent control(s)**, the stale file, and the regeneration command.

## Generation is REAL — no synthetic evidence (SC-006)

There is **no `[S]`/`[SEH]` task** for this feature. The gate compares regenerated bytes to
the on-disk bytes; parity is asserted against the real captured pre-migration rows
(`readiness/parity-fixtures/`); the correspondence test reads the real
`FS.Skia.UI.Controls.Typed` surface. The Synthetic-Evidence Inventory in `tasks.md` is
empty.
