# Phase 1 Data Model: Typed-Controls Plan Closeout

This feature ships **no code entities** (no records, DUs, or MVU types). Its "entities" are
the **documentation/governance artifacts** it authors or refreshes, plus the read-only source
references they describe. Each artifact below lists its fields (sections/frontmatter), the
validation rules it must satisfy (which gate enforces them), and its lifecycle.

- **Generated peer**: `.claude/skills/fsharp-code-generation/SKILL.md` (regenerated, never
  hand-edited)

  `compatibility` (build/Governance scope), `metadata.{author,source}`.

## A2 — `fs-skia-reconciliation` skill (new) — US3

- **Canonical file**: `.agents/skills/fs-skia-reconciliation/SKILL.md` (NEW)
- **Generated peer**: `.claude/skills/fs-skia-reconciliation/SKILL.md` (NEW, regenerated)
- **Frontmatter** (required for registry discovery): `name: fs-skia-reconciliation`, a
  `description` (one line, used for recall/match), `compatibility` (e.g. "F# net10.0;
  FS.Skia.UI.Controls package, internal module — no public surface"), `metadata.{author,
  source}` (`source: specs/074-typed-controls-plan-closeout/plan.md` or the 067 plan).
- **Content sections** — MUST teach, per FR-009:
  - **Invariants**: pure / total / deterministic; identity-at-rest (`diff x x` is a no-op
    patch); round-trip (`apply prev (diff prev next).Patch` ≡ `next` up to attr ordering).
  - **Key handling**: key-first-then-positional child matching; `Kind`-mismatch ⇒ whole-subtree
    `Replace`; duplicate keys ⇒ `KeyCollision` diagnostic (never throws).
  - **Operation set**: `NodePatch` (`Keep`/`Replace`/`Update`), `ChildOp`
    (`ChildKeep`/`ChildMove`/`ChildInsert`/`ChildRemove`), `UpdatePatch`/`FieldChange`/
    `AttrChange` — including the prev-list vs. next-list index conventions.
  - **Property-test approach**: totality, determinism, identity-at-rest, key-collision
    diagnostics; tests reach internals via `InternalsVisibleTo("Controls.Tests")`.
  - **Disposition** (the single source for the module's status): `module internal`,
    property-tested, **deliberately unwired** from the render path, **parked** (intentional,
    not abandoned); render/diff-path integration is **deferred, out-of-scope future work**,
    and the skill names the integration point it would touch.
- **Validation rules**: `SkillSyncCheck`, `SkillQualityCheck`, `SkillContractPathCheck`;
  registry discovery via frontmatter `name:` (no hardcoded-list edit). After regen, the skill
  index (`.claude/skills/GENERATED.md` and the skillist-reference) lists it.
- **Lifecycle**: create canonical → `RefreshSurfaceBaselines` (discovers + generates peer +
  refreshes index) → gates green.
