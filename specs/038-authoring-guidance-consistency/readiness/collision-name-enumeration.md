# Collision-Prone Public-Name Enumeration (T007, research R3)

Skills loaded before this analysis: `fs-skia-skiaviewer`
(`src/SkiaViewer/skill/SKILL.md`), `fs-skia-elmish` (`src/Elmish/skill/SKILL.md`),
`fs-skia-keyboard-input` (`src/KeyboardInput/skill/SKILL.md`). See
`skill-loading-evidence.md`.

## Method

A name collides with ordinary consumer code only if `open <namespace>` brings it
into the consumer's *unqualified* scope. Two cases:

- **Union cases** of a DU declared directly in the namespace are imported
  unqualified by `open <namespace>` → collision-prone.
- **Module-bound values** (`Viewer.update`, `ElmishAdapter.init`, …) are imported
  unqualified **only** if the enclosing module is `[<AutoOpen>]`. A plain
  `module M =` requires the consumer to write `M.update`, so it never shadows a
  bare consumer `update`.

`grep -n AutoOpen` over `src/SkiaViewer`, `src/Elmish`, `src/KeyboardInput`
(`.fs` + `.fsi`) returns **no matches**. Therefore every `update`/`init`-bearing
module below is already module-qualified.

## Conclusion

- **Hardened:** `ViewerWindowStartupState` gets `[<RequireQualifiedAccess>]` in
  `src/SkiaViewer/SkiaViewer.fsi` + `.fs`. This is the one real shadow (the
  author hit a bare `Normal`). RQA also qualifies its sibling cases consistently.
- **Elmish decision (recorded explicitly):** the `ElmishAdapter.update`/`init`
  surface is **already module-qualified** (no `[<AutoOpen>]`), so it needs no RQA
  and its baseline `FS.Skia.UI.Elmish.txt` is **intentionally omitted** from the
  refresh — no Elmish surface change.
- **KeyboardInput decision:** `Keyboard.*`/`ViewerKeyboard.*` are
  module-qualified — no change; `FS.Skia.UI.KeyboardInput.txt` is not modified.

## Surface-baseline files to refresh (US3)

`[<RequireQualifiedAccess>]` does **not** change an exported *type name*; the
curated baselines list type full-names, and `PackageSurfaceCheck` is a presence
check (`runPackageSurfaceReport`). So:

- `readiness/surface-baselines/FS.Skia.UI.SkiaViewer.txt` — unchanged (type
  `ViewerWindowStartupState` is not even in the curated list; the 5 listed types
  keep their names).
- merged `readiness/surface-baselines/FS.Skia.UI.txt` — regenerated by
  `scripts/refresh-surface-baselines.fsx` from the rebuilt `FS.Skia.UI.dll`; no
  diff expected (RQA adds no exported type).
- `FS.Skia.UI.Elmish.txt`, `FS.Skia.UI.KeyboardInput.txt` — **not** modified
  (no surface change).

The evidence for US3 is therefore the **consumer compile fixture**
(FAIL-before / PASS-after, `readiness/fsi/`), not a baseline diff.
