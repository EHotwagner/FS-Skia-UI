# Implementation Plan: Controls Authoring API Discoverability

**Branch**: `106-controls-api-discoverability` | **Date**: 2026-06-12 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/106-controls-api-discoverability/spec.md`

## Summary

Make the FS.Skia.UI Controls authoring surface discoverable to a `dotnet new
fs-skia-ui` consumer so a coding agent never has to reflect over the DLL to author
controls. Three coordinated fixes, plus a durable guard:

1. **Demonstrate the typed front door** — rewrite the generated starter
   (`template/base/src/Product/View.fs`) to author controls through
   `FS.Skia.UI.Controls.Typed` `Props`/`view` (the compiler-guided path). The
   typed `.fsi` is *already* bundled into the consumer's
   `docs/api-surface/Controls/` (feature 089), so this story is about making the
   demonstrated default match the discoverable surface, not new bundling.
2. **Document the public surface** — replace the 186 placeholder
   *"Public contract function exposed by this FS.Skia.UI package."* `///` summaries
   across the 13 public Controls `.fsi` files (incl. the `Catalog` discovery API)
   with substantive per-member documentation that ships in `FS.Skia.UI.Controls.xml`
   and therefore reaches IntelliSense and offline agents.
3. **Surface the catalog facts** — bundle a consumer-visible per-control catalog
   reference into the generated project and point the README at it + the documented
   `Catalog.*` discovery API, so "which attributes does this control take" is
   answerable from shipped docs.
4. **Guard it** — add a `ControlsDocCoverageCheck` governance gate (single
   governance home, routed into the controls-public-surface set) that fails the
   build on any placeholder / empty / duplicate-only summary on the Controls public
   surface, so the documented surface cannot regress to boilerplate.

The typed front door already lowers structurally to the legacy builders (proven by
`tests/Controls.Tests/TypedLoweringTests.fs`), so the starter migration is
behavior-preserving — the generated product renders the same controls.

## Technical Context

**Language/Version**: F# / .NET `net10.0`
**Primary Dependencies**: No new dependencies. Reuses `FS.Skia.UI.SkillSupport`
(`Globbing`, `Parsing`) for the gate's file scan; `YamlDotNet` (already used by
`Capabilities`/`CatalogGen`) for any catalog read; the compiled FAKE front end
(`FS.Skia.UI.Build`, `build/Governance/**`) for the gate + routing.
**Testing**: Expecto governance tests for the new gate (red-before/green-after over a
fixture with a planted placeholder); existing `TypedLoweringTests` parity proves the
starter migration is structurally identical; `GeneratedProductCheck` /
`TemplateCheck` exercise the regenerated starter + bundled catalog reference; FSI
transcript unaffected.
**Target Platform**: Windows and Linux (no platform-specific surface).

### Repository Governance Decisions

- **Template ownership**: The generated template changes — `template/base/src/Product/View.fs`
  is rewritten to the typed front door, `template/base/README.md` gains a populated
  discovery pointer, and a consumer-visible catalog reference is added under
  `template/base/docs/`. `template/capabilities.yml` already enrolls the typed
  `Widgets/*.fsi` contracts (feature 089) so no capability-row change is needed for
  the typed surface; the catalog reference is added as bundled template content.
  `.template.config/template.json` is reviewed for new content includes (the catalog
  reference file) and updated if the template manifest must list it.
- **Dependency impact**: N/A — no dependency change. No `Directory.Packages.props`,
  `docs/dependencies.md`, or `DependencyReport` change; no new package reference is
  introduced (the gate reuses already-referenced `SkillSupport`/`YamlDotNet`).
- **Command-surface impact**: `build.fsx`/`build/Governance/**` change — a new
  `ControlsDocCoverageCheck` target is added to `Targets.fs` (DU + `allTargets` +
  `name` + `directPrerequisites` + `routableGates`), routed in `Routing.fs` under the
  controls-public-surface rule, implemented in a new `ControlsDocCoverage.fs`, and
  wired through `Engine/Update.fs` + `Engine/Interpret.fs`. `validation.contract.yml`
  is regenerated (not hand-edited) by `./fake.sh build -t RefreshSurfaceBaselines`;
  `TargetMetadataDrift` enforces currency. The api-surface bundle is regenerated by
  the same `RefreshSurfaceBaselines` run (`ApiSurfaceGen`). FAKE-backed targets run
  sequentially in the deterministic order; the escalated controls-public-surface set
  + `GeneratedProductCheck` + `TemplateCheck` + `EvidenceGraph` + `EvidenceAudit`
  apply. Example order:
  1. `./fake.sh build -t Dev`
  2. `./fake.sh build -t Route` (confirm escalation + gate list), then the routed gates
- **Generated project impact**: The default generated product changes — the starter
  view authors via the typed front door, the README points to the discovery
  mechanism, and the generated `docs/` carries the catalog reference. No change to
  selected-Controls guidance logic, local skills, placeholder/excluded-history scans,
  or generated `Dev` behavior beyond the new starter compiling + rendering.
- **Evidence paths**:
  - `specs/106-controls-api-discoverability/readiness/doc-coverage.md` — the new
    gate's report: enumerated Controls public surface, member count, 0 placeholder /
    empty / duplicate-only findings.
  - `specs/106-controls-api-discoverability/readiness/generated-product.md` —
    `GeneratedProductCheck` evidence that the regenerated starter compiles and renders.
  - `specs/106-controls-api-discoverability/readiness/template-check.md` —
    `TemplateCheck` evidence the bundled catalog reference + README pointer are present.
  - `specs/106-controls-api-discoverability/readiness/surface-baselines.md` —
    api-surface bundle currency (`ApiSurfaceGen.currency`) + per-package baseline
    stability after doc-only `.fsi` edits.
  - `specs/106-controls-api-discoverability/readiness/evidence-audit.md` — merge-gate
    verdict token (synthetic propagation + diff-scan), `EvidenceGraph` DAG.
- **`.fsi` / contract impact**: `///` doc comments are added/replaced across the 13
  public Controls `.fsi` files and `Catalog.fsi`. **No `.fsi` signature *shape*
  changes** (no added/removed/retyped members). Per-package surface baselines
  (`readiness/per-package-surface/FS.Skia.UI.Controls.fsi.txt`) are expected to stay
  byte-stable because `PerPackageSurface.normalize` strips `//`-prefixed comments
  (incl. `///`) before diffing — doc-only edits do not churn the baseline. The
  api-surface *bundle* (`template/base/docs/api-surface/Controls/*.fsi`) copies `.fsi`
  verbatim **with** comments, so it MUST be regenerated and its currency check passes
  after the doc edits. Compatibility: additive documentation only; no migration
  guidance needed (no behavior or signature change).
- **MVU/effect boundary**: N/A — the feature adds no stateful or I/O-bearing product
  workflow. The new gate is a pure analysis (`.fsi` text → findings) executed at the
  existing FAKE interpreter edge (`Engine/Interpret.fs`), matching the established
  gate pattern (`PerPackageSurface`, `CatalogDocsGen`); no `Model`/`Msg`/`Effect`
  surface is introduced for the product.
- **Synthetic evidence**: None planned. The gate runs against the **real** Controls
  `.fsi` files; the starter migration is proven by the **real** existing
  `TypedLoweringTests` parity suite; `GeneratedProductCheck` renders the **real**
  generated product. The gate's failing-first test plants a placeholder in a **test
  fixture** (a temp/sample `.fsi`), not a mock of the surface — this is ordinary
  red-before/green-after test data, not `[S]` synthetic evidence. No `[S]`/`[SEH]`
  anticipated; if any arises it gets full Principle V disclosure.
- **Test evidence**: (1) `ControlsDocCoverage` governance test — fails before the gate
  logic exists / when a planted placeholder is present, passes after the 186
  placeholders are replaced and the gate is wired. (2) Reuse `TypedLoweringTests`
  parity for the migrated starter controls. (3) `GeneratedProductCheck` packed
  generated-product render. (4) `TemplateCheck` for bundled catalog reference + README.
- **Observability**: The gate emits an actionable report (`readiness/doc-coverage.md`)
  naming each offending file + member + reason (placeholder / empty / duplicate-only)
  rather than a bare pass/fail, so a future contributor sees exactly which member
  regressed. Missing-artifact-class failure if the report is absent. The README
  pointer is a concrete, resolvable path (no "see API reference" dead end — FR-013).
- **Deferred scope**: Documenting the **non-Controls** boilerplate (the other ~204
  `"Public contract function exposed"` occurrences across `src/**/*.fsi` outside
  Controls) is deferred — this feature scopes the gate + doc rewrite to the Controls
  public surface (the surface that triggered the reflection incident). Migrating the
  remaining non-starter controls to the typed front door, bundling the Color / Input /
  SkillSupport capability `.fsi`, and any fsdocs HTML site work are deferred bounded
  follow-ups, recorded in the spec's Assumptions / Unsupported scope.

### Routing expectation

`./fake.sh build -t Route` will **escalate** to the controls-public-surface tier
(triggered by `src/Controls/**/*.fsi`, `template/**`, and `build.fsx`/`build/**`
governance paths) and additionally surface `GeneratedProductCheck`, `TemplateCheck`,
`TargetMetadataDrift` (contract regen), `EvidenceGraph`, and `EvidenceAudit`. Run only
the gates `Route` prints, sequentially, in the documented order.
