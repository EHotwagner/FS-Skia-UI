# Usage coherence (080) — claims match decoded content

- **Authoritative command**: `./fake.sh build -t ControlsCatalogDocsCheck` (prose currency) +
  `./fake.sh build -t ControlFidelityCheck` (decoded-content verdict).
- **Artifact path**: `docs/controls/<id>.md` Preview sections; decoded verdicts in
  `readiness/control-fidelity.md`.
- **Failure class**: an overclaim — prose describing content not visibly present in the decoded
  image — is a visual-evidence-honesty defect.

## Coherence result (T025)

The generated catalog detail-page Preview sections (`docs/controls/*.md`, regenerated by
`CatalogDocsGen`) make only a **generic, decodable-by-construction** claim: each is "a
deterministic render-only preview (320×160) … rendered against the default `DesignTokens.Light`
theme". After feature 080 that claim is now backed by faithful, control-specific geometry
(decoded in `control-fidelity.md`), where in 079 it sat over a label-on-a-box. No per-control
prose asserts specific visual content that the decoded image lacks. `ControlsCatalogDocsCheck`
passes (prose ↔ catalog ↔ index ↔ preview currency, byte floor) and `ControlFidelityCheck`
passes (decoded content matches each signature).

`custom-control` is presented honestly as **`Unsupported`**: its detail page carries the
`preview-status: unsupported` marker, it commits **no image**, and its `FidelityDeclaration` is
`UnsupportedNoPreview` (the gate asserts no committed PNG exists for it). No control fabricates
a depiction it cannot render.

## 079 overclaim correction

Feature 079 shipped previews that were uniform label-on-a-box schematics while its readiness
prose implied per-control content that was never decoded. Feature 080 supersedes that: the
previews are faithful, the per-control content is **decoded and asserted** by
`ControlFidelityCheck`, and the 079 readiness files carry a correction note pointing here (see
`specs/079-doc-preview-examples/readiness/real-image-evidence.md`).
