# Phase 1 Data Model: Frame Scheduler & Phase-Invalidation Model

This feature adds **one** public DU and **four** public `FrameMetrics` fields (one
cause + three phase booleans; the fourth phase reuses the existing `ViewCalled`), and
**one** internal view-tree cache. No new package, no MVU type change.

## Entity: `FrameCause` (public, `ControlsElmish.fsi`) — new

```fsharp
[<RequireQualifiedAccess>]
type FrameCause =
    | Idle
    | PointerMove
    | PointerDiscrete
    | Key
    | Tick
    | Resize
    | Theme
```

| Aspect | Value |
|--------|-------|
| Visibility | public (declared in `ControlsElmish.fsi`). |
| Equality | structural (a payload-free closed DU); compared directly in goldens/tests. |
| `RequireQualifiedAccess` | required — `Key`/`Tick`/`Idle` would shadow a consumer `Msg` on `open` (mirrors `FrameInput`). |
| Deterministic | yes — classified from the producing frame branch; identical scripts → identical cause sequence (FR-001/SC-001/SC-005). |
| Corpus coverage | `Perf.runScript` produces `Idle`/`PointerMove`/`PointerDiscrete`/`Key`/`Tick`; `Resize`/`Theme` are live-only (the trigger is the live scheduler, not a `FrameInput`). |

## Entity: `FrameMetrics` (public, `ControlsElmish.fsi`) — extended

Post-feature shape (current fields + the new ones):

| Field | Type | Semantics |
|-------|------|-----------|
| `ProductModelChanged` | `bool` | A product message changed the model this frame (unchanged). |
| `ViewCalled` | `bool` | **The view phase.** `host.View` actually ran. **Narrows**: now `false` on a model-unchanged frame (incl. an animation-only tick, formerly `true`) because the scheduler reuses the already-produced view tree (FR-003/FR-011). |
| `FullRenderCount` | `int` | Genuine `host.View` + `Control.renderTree` materializations (unchanged definition). **Drops** to `0` on an animation-only tick (no view ran). |
| `RemeasuredNodeCount` | `int` | From the retained step's `WorkReduction` (unchanged). |
| `PointerSamplesReceived` | `int` | Raw native samples incl. deferred moves (unchanged). |
| `PointerMovesProcessed` | `int` | ≤ 1 per burst frame (unchanged, FR-006). |
| `FullRenderFallbackCount` | `int` | Feature-110 retained-routing fallback count (unchanged). |
| **`FrameCause`** | **`FrameCause`** | **NEW (FR-001).** The trigger that caused this frame. Deterministic, golden-asserted. XML-doc required. |
| **`DiffRan`** | **`bool`** | **NEW (FR-002).** The keyed reconciler reconciled a newly-produced view tree this frame (⟺ `ViewCalled` in this pipeline; a distinct field for the explicit phase record). |
| **`LayoutRan`** | **`bool`** | **NEW (FR-002).** ≥1 node was re-measured this frame. Set explicitly by the scheduler (not inferred from `RemeasuredNodeCount` at read time). |
| **`PaintRan`** | **`bool`** | **NEW (FR-002).** The painted scene (model render) or the animation overlay was (re)assembled this frame. `true` on model frames AND animation-only ticks; `false` on idle / pure routing frames. |
| `FrameDuration` | `TimeSpan` | Real wall-clock; excluded from goldens (unchanged). |

**The phase record** is the four booleans `{ ViewCalled, DiffRan, LayoutRan,
PaintRan }`. Hit-test is intentionally NOT a field (clarified — see the contract).

**Construction/read sites to update** (every one, in the same change, or the build
breaks): Perf `zero` (`ControlsElmish.fs:1231`), coalesced move (`:1247`), tick
(`:1273`), key (`:1307`), discrete (`:1325`); live `emitFrameMetrics`
(`ControlsElmish.fs:918`); test serialize `Feature109CorpusTests.fs:153`; surface
baseline `readiness/surface-baselines/FS.Skia.UI.Controls.Elmish.txt` (gains the
`FrameCause` type + cases) + per-package baseline
`readiness/per-package-surface/FS.Skia.UI.Controls.Elmish.fsi.txt` (regenerated by
`RefreshSurfaceBaselines`).

**Validation rules**: an `Idle` frame has all four phase bools `false` and
`FrameCause = Idle` (SC-002); an animation-only tick has `ViewCalled = false`,
`DiffRan = false`, `PaintRan = true` (SC-003); a model-changing frame has
`ViewCalled = true`, `DiffRan = true`, `PaintRan = true` (SC-004). The cause + phase
fields re-run byte-identically (SC-005). Adding the DU + fields is a **breaking**
`.fsi` change (Tier 1) but not a behaviour change to rendered output (FR-008).

## Entity: Reused view tree (internal, `Controls.Elmish` live loop)

| Aspect | Value |
|--------|-------|
| Visibility | internal (a `ref` in the `runInteractiveApp` closure, the interpreter edge). |
| Key | `(model-reference, size)` — `obj.ReferenceEquals(model, cachedModel) && size = cachedSize`. |
| Value | the **un-stamped** `host.View size model` output for the current model. |
| Reuse rule | on a paint where the key matches, reuse the cached tree and skip `host.View`; otherwise call `host.View` and refresh the cache. The full-tree `applyRuntimeVisualState` stamp + `RetainedRender.step` ALWAYS run (only `host.View` is skipped). |
| Fallback | a value-type model (`ReferenceEquals` always `false`) or any changed/uncertain key re-runs `host.View` — byte-identical, no optimization (the deterministic view-skip evidence is the Perf path, not this best-effort cache). |

**Validation rule**: the rendered scene produced via the reused tree is byte-
identical to the scene a fresh `host.View` + stamp + step would produce (FR-008/
SC-007), because `host.View` is pure in `(model, size)`.

## Entity: Per-frame classification (internal, `Controls.Elmish`)

For each produced frame the scheduler computes, deterministically:

- `FrameCause` — from the producing branch (R1 table).
- `ViewCalled` — `host.View` ran (false on model-unchanged frames after the view-skip).
- `DiffRan` — a new view tree was reconciled (⟺ `ViewCalled`).
- `LayoutRan` — `RemeasuredNodeCount > 0`, set at construction.
- `PaintRan` — a model render or an animation overlay was assembled.

## State / lifecycle

No new persistent state beyond the internal view-tree cache `ref` (live loop) and the
existing `retained`/`lastRender`/`pendingMove` refs. `Perf.runScript` derives the
cause/phase from its existing per-frame fold (no new mutable state). Per-identity
animation/text state in `RetainedRender.StateByIdentity` is unchanged.
